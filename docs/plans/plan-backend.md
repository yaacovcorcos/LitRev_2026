# Backend Infrastructure & Schema Plan

## Current Architecture
*How this domain works right now, based on actual committed code.*

- **Transport:** Server Actions are the primary transport, but all business logic lives in a server-only service layer (`lib/server`). This enables future Route Handlers + fetch without refactors.
- **Server Action Export Contract:** `app/actions/**` modules marked `"use server"` must export runtime action functions only; shared type contracts come from non-action modules (for example `lib/schemas/**`) to avoid runtime action-registration failures.
- **Database:** Supabase PostgreSQL accessed via Prisma. Pooled connection string (`DATABASE_URL`) with SSL + pgbouncer. Direct string (`DIRECT_URL`) for migrations.
- **Environment split:** Local localhost DB is for development/testing only. Deployed source of truth is Supabase Postgres, and production schema changes must target production `DIRECT_URL` (not local URLs).
- **Data Persistence:** Replaced initial LocalStorage architecture with full database persistence for Projects, Protocols, Studies (Ledger), Drafts, and Copilot states.
- **File Assets:** Supabase Storage bucket `study-assets` is private for canonical tenant-scoped assets, file deletes automatically purge canonical server-owned blobs, and storage identity is server-owned. Study uploads enforce the PDF/DOCX contract server-side with byte-signature validation and canonical stored MIME types before any blob write. Clients do not submit `storagePath`; `FileAsset.storagePath` remains server-only metadata, privileged reads validate canonical project/study namespace before service-role fetch, canonical client access now flows through authenticated app-owned download routes instead of direct storage object URLs, file downloads default to attachment/no-sniff delivery, legacy compatibility is limited to the explicit `external/demo/*` seed namespace, `downloadUrl` is the user-facing file access contract for canonical rows, and `publicUrl` is reserved for explicit external/demo or future true public/share surfaces.
- **Search Metadata Truthfulness Contract:** Search adapters may now return `SearchResult.year` as unknown when the source metadata is missing or malformed; PubMed, OpenAlex, and Semantic Scholar no longer fabricate the current year. Tool output contracts accept yearless search and recommendation results, OpenAlex and Semantic Scholar now omit `totalResults` when local year-range filtering means the runtime cannot truthfully derive a filtered total, receipt/timeline wording distinguishes `returned` page counts from truly `found` totals when totals are unknown, PubMed checkpoints now distinguish total-result-set claims from returned-page claims, Crossref no longer treats record `created` timestamps as publication years, and ledger persistence preserves provider provenance for provider-backed search results instead of collapsing OpenAlex into generic `copilot`. Search pagination now uses one provider-agnostic `cursor`/`nextCursor` contract at the tool boundary: `nextCursor` is opaque to the agent, offset-style providers validate numeric continuation tokens server-side, and tools do not advertise continuation unless they can consume it on the next call. Ledger persistence remains stricter than search recall: `add_to_ledger` skips yearless results with explicit reporting while title+year dedupe only applies when a trustworthy year exists and identifier-based dedupe continues to work without one.
- **Study PDF Processing:** Ledger PDF extraction/analysis now run through a study-specific durable queue contract backed by `StudyProcessingJob`. UI-triggered import/extract/analyze enqueue async work, one dispatcher invocation claims at most one job with a renewable lease, and all ledger surfaces consume one derived `Study.processing` snapshot rather than inferring transient state from request-local action results. In deployed environments, cron ingress and internal dispatcher execution remain separate trust boundaries: cron requests use `CRON_SECRET` on `GET /api/cron/study-processing`, internal kicks use `STUDY_PROCESSING_INTERNAL_TOKEN` on `POST /api/internal/study-processing`, and request metadata such as `x-vercel-cron` is not treated as authentication. Local non-deployed development may fall back to a direct in-process one-job kick when dispatch config is incomplete so queued ledger work still progresses without hidden local secret setup. Preview and production dispatch secrets are provisioned, while repo-managed minute cron scheduling remains tier-gated and is not enabled in committed config on the current Vercel plan.
- **PDF Extraction Model Controls:** Study PDF quick extraction and deep analysis default to `grok-4-1-fast`. Operators can set `AI_PDF_EXTRACTION_MODEL` for both stages, or override stages independently with `AI_PDF_QUICK_EXTRACT_MODEL` and `AI_PDF_DEEP_ANALYSIS_MODEL`; blank values are ignored so the safe default remains active.
- **Local ledger import drift handling:** Local PDF import now distinguishes post-upload processing/readback drift from plain upload failure. When local schema is behind, the import action returns a typed `LOCAL_SCHEMA_DRIFT` failure with explicit `npx prisma migrate dev` guidance instead of surfacing an opaque post-import error, while plain study-file upload remains a storage/validation path.
- **Schema:** Multi-tenant setup. Core models include `User`, `Workspace`, `WorkspaceMember`, `Project`, `Protocol`, `Draft`, `DraftVersion`, `DraftCheckpoint`, `Study`, `FileAsset`, `AIConversation`, `AIMessage`, `AIUsage`, `UserMemory`, `ProjectMemory`, `StudyMemory`, `ConversationSummary`, `MemoryRetrieval`, `MemoryEmbedding`, `AgentRun`, `RunEvent`, `Artifact`, `AutonomyConfig`, and `Note`.
- **Draft Versioning:** `DraftVersion` stores immutable per-section snapshots for auditing/recovery. The `draft_diff` artifact apply flow writes to `DraftVersion` (provenance) + `Draft` (display). Notes table is no longer used for draft backup.
- **Draft Proposal Contract:** Newly generated `draft_diff` artifacts now carry deterministic `sectionKey` metadata plus a base-section snapshot, accepted applies reject stale target-section changes instead of silently overwriting newer draft text, and successful apply also persists a whole-draft `DraftCheckpoint` with `kind="ai_apply"` linked back to the accepted artifact/conversation for restore-grade provenance.
- **Draft Persistence Contract:** `Draft.state` now normalizes to `DraftState v2`, where a canonical `manuscript` document is stored alongside a derived `contentBySection` compatibility projection. Legacy `v1` payloads migrate on read/write, editor block nodes preserve `blockId` attrs, and direct draft writers (for example demo seed + ledger citation rewrites) normalize through the same contract.
- **Draft Export Contract:** Draft export now runs server-side from normalized canonical manuscript state, not client-side DOM/route serialization. DOCX and Markdown share one compiled export model, generated files are real `FileAsset` uploads, visible draft export history remains DOCX-only in the current UI, and bibliography rendering uses a CSL-backed formatter while LitRev keeps citation order/numbering authority.
- **Draft Diagnostics Contract:** Draft/export quality diagnostics now compile from one canonical normalized report. Citation-derived diagnostics reuse the existing `CitationIssueType` taxonomy, advisory section-readiness signals stay warning-only and heuristic, and strict export blocking remains limited to current citation-integrity failures.
- **Draft Checkpoint Contract:** `DraftCheckpoint` stores immutable whole-draft authoring-state snapshots separate from `DraftVersion`. Restore rebuilds a full valid `DraftState v2` from checkpoint authoring fields plus current/default non-authoring state, `contentBySection` is rebuilt from checkpoint `manuscript`, export-created checkpoints link back to generated `FileAsset` rows, and no route/UI state is revived on restore. Today this remains a backend/service foundation plus export provenance path; the draft page does not yet ship a user-facing checkpoint history/compare/restore action surface.
- **Auth & Identity Boundary:** Better Auth (Prisma adapter, DB sessions) is live with Google + magic link support, server-side `withAuth()`/`requireApiSession()` boundaries, and request-scoped actor context (`AsyncLocalStorage`) that feeds service scope resolution. Magic-link delivery treats returned provider errors as request failures, so the auth UI cannot report a successful send when Resend rejected the message; the transactional email provides clear request context, a primary sign-in action, a fallback URL, expiry guidance, and an ignore-if-unrequested notice. Protected page routing validates the Better Auth session directly in `proxy.ts` before rendering the app shell, without a loopback HTTP call; session cookie-name presence alone is not an authentication boundary. If proxy-level validation is transiently unavailable, the request is allowed to continue to the server-enforced page/action/API boundaries rather than clearing cookies or forcing a misleading login redirect. Auth origin configuration keeps deployed `baseURL` values explicit, but local development uses request-origin auth with common localhost origins trusted on any port so the browser, magic links, and auth callbacks do not silently split across local servers.
- **Legacy Claim Path:** First authenticated session runs an idempotent transactional claim that reassigns `local-user`/`local-workspace` ownership, backfills denormalized workspace IDs, and removes obsolete placeholder principal rows.
- **Demo Seed Lifecycle:** Sample-project creation/reset is server-seeded from a single transactional service (`lib/server/demo-project.ts`) that finds the current user's scoped demo by `Project.demoKey`, creates a generated project ID when missing, and repopulates project, protocol, ledger, draft, notes, memory, and scoped seed conversation rows without relying on a global fixed project ID.
- **Onboarding State Persistence:** Guided setup is opt-in by default. User-level `UserMemory` (`guided_setup_new_projects`) can explicitly enable guided setup launch behavior, and per-project onboarding state persists in `Project.progress.onboarding` (`enabledOverride`, `completedAt`, `skippedAt`) for project-specific overrides and completion/skip tracking.
- **AI Rate Limiting (Current):** Limit checks and usage writes now support authenticated user/workspace scope (with legacy project fallback), while cache-efficiency counters remain process-local instrumentation in `lib/server/ai/rate-limiter.ts`. Provider-backed voice transcription now runs through the same backend governance boundary before provider calls: it validates the shared per-user/workspace AI gate, enforces a separate successful-transcription daily cap from persisted `AIUsage` rows, validates optional project attribution server-side, and records truthful zero-token `voice_transcription` usage rows instead of bypassing cost controls or inventing token counts.
- **Telemetry Ingest Contract:** Reliability and performance ingest now support dual actors: authenticated scoped telemetry and a narrow anonymous public-safe operational subset for home/auth route readiness. Telemetry actor resolution is side-effect-light and avoids auth-failure counting plus legacy-claim work; anonymous rows persist into `ChatUnificationMetric` with null identity.
- **Citation Preview Diagnostics:** Citation hover resolution returns server-owned diagnostics alongside `CitationMetadata`, caches successful diagnostics with the result, persists terminal completion/failure telemetry into `ChatUnificationMetric` under the `citation_preview.*` namespace, and ships repo-owned smoke/report/diagnose scripts for provider triage.
- **Citation Hover Continuation:** Citation hover remains bibliography-first and budget-bounded on the initial request, but retryable `PubMed` bibliography-only successes can now trigger one server-authoritative continuation attempt. Continuation is gated by paired existing server/client flags, server-side continuation requests dedupe by citation key, count-bearing cache state is monotonic under slower no-count retries, and continuation terminal telemetry/reporting track recovery without overstating failed-attempt outcomes.
