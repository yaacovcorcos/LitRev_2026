## Findings

- Severity: High
  Title: Full lint is improving but still not trustworthy enough for the protected `check` contract
  Why it matters: LitRev already enforces the phase-owned governance inventory inside `check`, but raw `npm run lint` still fails often enough that promoting it today would create noise instead of leverage.
  Evidence with file references:
  - `docs/plans/plan-lint-governance.md` already marks governance Phases 0-5 shipped.
  - `docs/runbooks/git-flow.md` documents `check` as the required protected status.
  - `npm run lint` on 2026-04-02 reported `126 errors` and `112 warnings` after this review's first cleanup pass.
  Whether it is new, recurring, or a regression: Recurring, but materially improved from the 2026-03-21 snapshot (`523 errors`, `591 warnings`).
  Required fix or containment: Keep raw lint out of the protected `check` contract until more baseline debt is intentionally removed or explicitly waived through owner docs.

- Severity: High
  Title: File-asset project scoping previously relied on unsafe substring matching
  Why it matters: Storage path validation is part of the repo's tenancy boundary. Substring checks can accept attacker-crafted paths that merely contain a project ID without actually belonging to that project's namespace.
  Evidence with file references:
  - `next-app/lib/server/files.ts` now normalizes path segments and enforces canonical `projects/<projectId>/...` scoping, optionally with the bucket prefix.
  - `next-app/lib/server/__tests__/files.test.ts` covers canonical acceptance and cross-project rejection cases.
  Whether it is new, recurring, or a regression: Previously open finding from the 2026-04-02 deep audit, now fixed in this implementation slice.
  Required fix or containment: Keep this validation server-owned and extend the same "normalize, then compare namespaces" approach to any future storage helper that crosses project boundaries.

- Severity: Medium
  Title: Baseline evidence needed a durable home outside `repo-health.md`
  Why it matters: repo health summaries become noisy and less trustworthy if they accumulate raw metrics, command transcripts, or review diaries.
  Evidence with file references:
  - `docs/reviews/repo-health.md` explicitly says it should remain concise and factual.
  - `docs/reports/repo-deep-audit-2026-04-02.md` and this review now hold the dated baseline detail instead.
  Whether it is new, recurring, or a regression: New process correction.
  Required fix or containment: Keep future deep-review detail in dated review/report artifacts and only fold validated current-state conclusions into `repo-health.md`.

- Severity: Medium
  Title: Mobile foundation e2e is currently blocked by dev quick-login failure
  Why it matters: the repo's mobile foundation suite is valuable, but at the moment it is not giving clean signal on UI regressions because the auth/bootstrap helper path is failing first.
  Evidence with file references:
  - `npm run test:e2e:mobile:foundation` on 2026-04-02 failed because `/api/dev/quick-login` returned HTTP 500 across the mobile auth, home, project shell, and protocol specs.
  - `next-app/e2e/helpers/foundation.ts` is the failing helper surface.
  Whether it is new, recurring, or a regression: Current local-environment blocker; regression status needs a dedicated follow-up once the helper failure is triaged.
  Required fix or containment: treat the suite as blocked-by-environment for this review and triage the helper path before using mobile foundation as a confidence signal for unrelated changes.
